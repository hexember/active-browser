## Goal
Add `Support/Info.plist` and a `Makefile` with the `build` / `bundle` / `run` / `clean` targets, so the Phase 2 executable can be assembled into a real `.app` and run for the first time as a background agent — `LSUIElement` in effect, `Bundle.main.bundleIdentifier` non-nil (self-filtering finally live) and `http`/`https` claimed in Launch Services. ## Spec (planner)

### Decisions to read before writing anything

**D1 — What is actually observable at the end of this task (read this before the Test Steps).**
`Project.md` §3 Phase 3 Verify step 2 says "a menu bar item appears". **That cannot happen in this task and must not be made to happen.** `MenuBarManager` / `NSStatusItem` is task 07 (Phase 5); adding a status item here would be code written outside an approved specification (guardrail §3, *No Orphan Implementations*) and would duplicate task 07's PR.

The honest observable outcome of task 03 is: **the app launches from the bundle and stays running as a background agent with no Dock tile** — `pgrep -x ActiveBrowser` prints a pid, `lsappinfo` reports it as a `UIElement`, no Dock icon, no ⌘Tab entry, no window — and its `UserDefaults` domain `com.local.activebrowser` appears and does **not** contain its own bundle id. That domain name is the proof `Project.md` Phase 3 actually asks for ("`Bundle.main.bundleIdentifier` is non-nil when launched from the bundle"): `UserDefaults.standard` resolves to the bundle id's domain, so a populated `com.local.activebrowser` domain proves the bundle id was read, `applicationDidFinishLaunching` fired, and the seeding in `AppDelegate.bootstrapIfNeeded()` ran.

**D2 — `pkill -x ActiveBrowser` is the only stop switch in this task.** There is no Quit menu item until task 07 and no `LSUIElement` app appears in ⌘Tab or the Dock, so a launched copy will otherwise run until logout. Every step that launches the app is paired with a `pkill` in the Reset block, and `make run` itself pkills first (D3).

**D3 — `make run` pkills before `open`; `make clean` does not pkill.** Deviation from `Project.md` §5's `run: bundle; open $(BUNDLE)`, deliberate and justified: `open <path>` on a bundle whose bundle id is already running **activates the running instance instead of launching the new binary**, so without the pkill you silently keep testing the previous build. `make install` in §5 already pkills, so this is house style, not a new idea. `make clean` deliberately keeps §5's shape (no pkill): `Project.md` Phase 3 Verify step 5 orders it as *quit first, then clean*, and after task 04 a pkill inside `clean` would also kill the user's installed menu-bar agent as a side effect of deleting build artefacts. Killing stays an explicit act by the tester (and, from task 07, the Quit menu item).

**D4 — nothing under `Sources/` or `Package.swift` changes in this task.** If the app misbehaves when first run from the bundle, that is a `[RE-PLAN REQUEST]`, not a quiet Swift edit here.

### Checklist

- [x] **`Support/Info.plist`** (new file, new directory — listed in `Project.md` §4). Reproduce `Project.md` §5 **exactly**; XML whitespace/formatting is free, key names and values are not:
      - `CFBundleIdentifier` = `com.local.activebrowser` — this string is load-bearing three times over: it is the `UserDefaults` domain, the id Launch Services registers, and the id `BrowserRegistry`/`URLDispatcher` compare against for self-filtering (guardrail §1).
      - `CFBundleExecutable` = `ActiveBrowser` — **must** match the SwiftPM product name and therefore the file copied to `Contents/MacOS/`. A mismatch makes the bundle launch-fail with a useless error.
      - `CFBundleName` = `ActiveBrowser`; `CFBundlePackageType` = `APPL`; `CFBundleShortVersionString` = `1.0.0`; `CFBundleVersion` = `1`.
      - `LSMinimumSystemVersion` = `13.0` (matches `platforms: [.macOS(.v13)]`; `SMAppService` in task 06 needs 13.0+).
      - `LSUIElement` = `<true/>` — a real plist **boolean**, not the string `"1"` and not `<string>YES</string>`. This is the *only* thing that makes the app an agent; `AppDelegate` deliberately does not call `setActivationPolicy` (task 02, D-note), so a wrong type here shows up immediately as a Dock icon.
      - `CFBundleURLTypes` = one dict with `CFBundleURLName` = `Web Link Handler` and `CFBundleURLSchemes` = `["http", "https"]`. Both schemes are required for the app to be eligible for the *Default web browser* list in task 04.
      - Add **no** extra keys: no `CFBundleIconFile`, no `LSHandlerRank`, no `NSPrincipalClass`, no `CFBundleDocumentTypes`, no `SMAppService`/`LaunchAgents` keys (task 06 uses `SMAppService.mainApp`, which needs none).

- [x] **`Makefile`** (new file, repo root — `Project.md` §4). Recipes use **real tab characters**. Variables exactly as `Project.md` §5:
      - `APP = ActiveBrowser`, `BUILD = .build/release/$(APP)`, `BUNDLE = build/$(APP).app`, and
        `LSREG = /System/Library/Frameworks/CoreServices.framework/Frameworks/LaunchServices.framework/Support/lsregister`.
      - `.PHONY: build bundle run clean` — **not optional.** The target `build` and the output directory `build/` collide: once `build/` exists, a non-phony `make build` prints `make: 'build' is up to date.` and silently skips the compile. Add a one-line comment saying so, and a note that any target added later (`install` in task 04, `release` in task 09) must be added to `.PHONY` too.
      - `build:` → `swift build -c release`. Keep it as the first target so a bare `make` builds.
      - `bundle: build` → in this order: `rm -rf $(BUNDLE)`; `mkdir -p $(BUNDLE)/Contents/MacOS`; `cp $(BUILD) $(BUNDLE)/Contents/MacOS/$(APP)`; `cp Support/Info.plist $(BUNDLE)/Contents/Info.plist`; `codesign --force --sign - $(BUNDLE)`. The `codesign` line must be **last** — the ad-hoc signature covers both payload files, and signing before the copies produces a bundle macOS refuses to launch. No `Resources/`, no `PkgInfo`.
      - `run: bundle` → `-pkill -x $(APP)` (leading `-`: make must not fail when nothing is running) then `open $(BUNDLE)`. See D3 for why the pkill is there.
      - `clean:` → `-$(LSREG) -u $(BUNDLE)` **before** `rm -rf .build build`. Leading `-` because `lsregister -u` errors when the path is already gone. Unregistering after deletion is a no-op, which is exactly the bug Phase 3 Verify step 5 checks for. Add a comment: the build copy claims `http`/`https` under the same bundle id as the installed copy, so leaving it registered lets Launch Services bind the default-browser role to a deleted path.
      - **Scope fence — targets that must NOT appear:** no `install:`, no `lsregister -f` anywhere (task 04); no `release:`, no `ditto`, no `shasum` (task 09); no `lsregister -kill`/`-r` database rebuild anywhere, ever (it is a system-wide rebuild and this task must not touch the user's Launch Services state beyond its own bundle); no `sudo`; no `defaults write`; no `setDefaultApplication` of any kind. `$(LSREG)` appears exactly once, in `clean`.

- [x] **Scope fence — verify nothing else changes:** `Sources/` and `Package.swift` are untouched (D4); no `UI/`, no `NSStatusBar`/`MenuBarManager` anywhere (task 07); no `ServiceManagement`/`SMAppService` (task 06); no `install.sh`, no `.github/` (Phase 6); no `Tests/`, no XCTest target; no `.gitignore` (see risks — flagged, not fixed here).

### Architectural notes and risks

- **`build` target vs `build/` directory.** The single most likely silent failure in this task; `.PHONY` is the fix and Test Step 5 is its regression check.
- **Duplicate Launch Services registration (`Project.md` §3 Phase 3, "Duplicate-registration gotcha").** From now on, two copies of bundle id `com.local.activebrowser` can exist (`build/` and, from task 04, `/Applications/`). `make clean`'s `lsregister -u` is this task's half of the fix; `make install`'s `lsregister -u $(BUNDLE)` is task 04's half. **Consequence for task 05:** default-browser behaviour is only ever tested from the `/Applications` copy.
- **This task creates real `UserDefaults` state for the first time.** The `com.local.activebrowser` domain is shared by the build copy and the future installed copy (same bundle id). The Reset block deletes it so tasks 04–06 still see a genuine first launch; leaving it behind would make "first launch seeds the registry" untestable later.
- **The app has no way to quit itself (D2).** Any launched copy survives until `pkill` or logout. There is no login item — task 02 shipped no `SMAppService` call — so a reboot also clears it; nothing persists across restarts from this task.
- **Registering an `http`/`https` handler does not change the default.** Claiming the schemes only makes the app *eligible*. Nothing here can hijack Arc. The `ai` steps read the current handler before and after purely as a safety assertion; they never write it.
- **Environmental linker warnings (carried from tasks 01–02).** This machine has CommandLineTools without Xcode, so every link step emits one or two `ld: warning: search path '/Library/Developer/CommandLineTools/Developer/...' not found` lines. Every warning assertion in this task counts warnings that are *not* those (`grep "warning:" LOG | grep -v "search path" | wc -l` → `0`).
- **`lsregister -dump` is large (~10 MB) and slow.** Dump once to a file and grep the file rather than re-dumping per assertion.
- **If `lsregister -dump` does not list the build copy's schemes after `make run`,** that is either a bad `CFBundleURLTypes` (a real defect in this task) or Launch Services indexing latency (re-dump after a few seconds). Do **not** "fix" it with `lsregister -f` (task 04) and **never** with `lsregister -kill -r` — a database rebuild is system-wide and risks the user's handler state. If it still does not appear, record the actual output and escalate rather than widening this task.
- **If `lsregister -dump | grep -c '<repo>/build/ActiveBrowser.app'` is non-zero after `make clean`,** record the count and raise a follow-up `fix/` task. Do not paper over it with a database rebuild.
- **Ad-hoc signing is intentional for v1** (`Project.md` Phase 6). It is enough for local launch; Gatekeeper/notarization only matters for the Phase 6 download paths.
- **`.gitignore` is still missing** (flagged by task 01). This task adds a *second* untracked build directory, `build/`, at the repo root. Adding `.gitignore` is a file outside `Project.md` §4, so it is **not** done here — main session: raise it as its own trivial task. Until then the git-agent must stage the three paths explicitly.
- **Registry may list non-browsers** (Zoom, Slack, script editors) in the seeded `includedBrowsers` — expected, and task 08's product surface. Not a defect of this task.
