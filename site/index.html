ActiveBrowser

A macOS menu bar app that opens every link in the browser you were just using.

curl -fsSL https://raw.githubusercontent.com/hexember/active-browser/main/install.sh | sh

Source on GitHub · Latest release

macOS 13 or later · Apple silicon · MIT licensed

Why

macOS allows exactly one default browser. So a link from Slack, Mail, Notes or Terminal always opens there, not in the browser you're working in.

Existing tools each ask you to decide something. Rules-based tools (Finicky, Velja) need rules you write and maintain. Pickers (Browserosaurus, Choosy, Bumpr) ask you on every link.

ActiveBrowser uses your recent focus instead. You already told the system which browser you're working in, by working in it.

When a rules-based tool is the better choice: if your routing depends on the URL, for example "all github.com links open in the work profile", use Finicky or Velja. ActiveBrowser never looks at the URL.

How it works

  1. It remembers the order in which you focus your browsers, from macOS app-activation notifications, with no polling.
  2. You set it as the default browser once.
  3. Each link goes to the most recently focused browser that is running. Otherwise it goes to the most recently focused one, which is launched. Otherwise it goes to your Fallback Browser, and otherwise to the first browser found.
  • A link is never dropped, and it is never routed back to ActiveBrowser itself.
  • It lives in the menu bar only: no Dock icon, no windows.
  • Idle memory is capped at 25 MB (typically about 12 MB).
  • It uses only Apple frameworks, with no third-party code.
  • The menu lets you include or exclude browsers and pick the Fallback Browser.
  • It adds itself as a login item on first launch from /Applications, so it is running before your first click. You can switch this off with Launch at Login in the menu.

Install

Run this in Terminal:

curl -fsSL https://raw.githubusercontent.com/hexember/active-browser/main/install.sh | sh

What the script does

  • Checks for macOS 13+, a supported CPU and a writable /Applications.
  • Resolves the latest release through the GitHub API, falling back to the latest-release redirect.
  • Downloads ActiveBrowser.app.zip and SHA256SUMS and verifies the checksum.
  • Extracts to a temp directory and checks the bundle id and architecture before anything is replaced.
  • Quits a running copy, replaces /Applications/ActiveBrowser.app, registers it with Launch Services and launches it.

It changes nothing else: no settings, no login items, no default-browser binding, no sudo. Running it again is the upgrade path.

Manual download

You can download the zip from Releases. The app is ad-hoc signed, not notarized, and a browser download is quarantined, so macOS will warn on first launch. The one-liner avoids this because curl does not quarantine.

Build from source

git clone https://github.com/hexember/active-browser.git
cd active-browser
make install

Intel Macs must use this route, because released builds are arm64-only.

Final step

Click the menu bar icon, choose Set as Default Browser, and accept the macOS confirmation dialog. The menu row then reads ✓ Default Browser.

Uninstall

Order matters — removing the login item while the app is still installed lets the next launch re-create it.

pkill -x ActiveBrowser
rm -rf /Applications/ActiveBrowser.app
defaults delete com.local.activebrowser   # optional: drop saved settings

Then System Settings → General → Login Items & Extensions → select ActiveBrowser → −, and set your real default browser back in System Settings → Desktop & Dock.

FAQ

Does it read or send my URLs?

No. It hands each URL to a browser without inspecting it. The app contains no networking code and no telemetry or analytics. It stores only your menu choices (included browsers, Fallback Browser, and a Launch at Login opt-out) in UserDefaults (com.local.activebrowser). Only installing goes online: the one-liner fetches install.sh from raw.githubusercontent.com, and the script downloads the release from GitHub (api.github.com, github.com, and GitHub’s release-download host).

Why is there no Gatekeeper prompt?

The app is ad-hoc signed, not notarized. curl doesn't set the quarantine attribute, so a curl-installed copy opens without a warning. Downloading the zip through a browser would quarantine it, so use the one-liner.

Why not Finicky or Velja?

Use them if your routing depends on the URL; ActiveBrowser routes by where you are working. See Why.

Does it handle other URL schemes?

No. Only http and https are handled; other schemes are left to the system.

What does this site collect?

Nothing. No cookies, no analytics, no third-party requests.
